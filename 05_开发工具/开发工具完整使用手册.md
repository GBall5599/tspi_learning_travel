# 泰山派 / RK3566 开发工具完整使用手册

> **适用范围**：`网盘资料\第07章.【立创·泰山派】开发工具` 与 `05_开发工具` 两个目录中现有的开发工具、压缩包、源码和辅助资料。  
> **盘点日期**：2026-07-25。本文说明的是目录内版本，并不把它们等同于当前最新版本。  
> **推荐原则**：日常只保留一套稳定链路——**串口使用 MobaXterm、Windows 烧录使用 DriverAssitant + RKDevTool 2.96、Linux 烧录使用 rkdeveloptool 或 upgrade_tool**。其余工具按需要使用；Secure Boot / eFuse 默认不碰。

## 1. 先建立正确的连接概念

这些工具面向的接口不同，不能互相替代：

| 目标 | 连接方式 | 典型工具 | 何时使用 |
|---|---|---|---|
| 看开机日志、进入 U-Boot / Buildroot Shell | USB 转串口（CH340） | **MobaXterm** | 板子无法启动、调试启动过程、无网络时 |
| 登录已启动系统 | 以太网 / Wi-Fi / USB RNDIS 网络 | MobaXterm（SSH/SFTP） | 日常文件传输、命令执行、远程开发 |
| 给 RK3566 写入 eMMC / SPI NOR 固件 | USB OTG，板子处于 **Loader 或 Maskrom** | **RKDevTool**、`upgrade_tool`、`rkdeveloptool` | 首次烧录、救砖、升级完整固件 |
| 调试 Android 系统 | ADB USB 或 TCP/IP | `adb`、`scrcpy` | 仅 Android 镜像启用了 `adbd` 时 |
| 从 TF 卡启动或升级 | 读卡器 + TF 卡 | SDDiskTool、Win32 Disk Imager | 厂商要求 SD 升级卡或写入原始 `.img` 时 |

### 1.1 术语

- **Loader 模式**：RockUSB 下载模式；设备已有可工作的引导程序，通常可直接烧录。
- **Maskrom 模式**：芯片 ROM 的底层恢复模式；适合 Loader 损坏或“救砖”。进入方式由泰山派硬件按键/跳帽决定，**先断电，再按板卡资料操作后上电并接 OTG**。
- **`update.img`**：Rockchip 打包固件，包含 Loader、分区表和若干镜像；适合“整包升级”。
- **分区镜像**：如 `uboot.img`、`boot.img`、`rootfs.img`、`kernel.img`；适合仅更新一个组件。
- **烧录前的硬规则**：使用可传数据的 USB 线、不要经过不稳定的 Hub、不要在烧录中断电；**镜像必须明确对应 RK3566、板型和存储介质**。

## 3. Windows 日常链路：驱动、串口、SSH

### 3.1 DriverAssitant（RockUSB 驱动）

**用途**：让 Windows 在板子进入 Loader/Maskrom 后识别为 Rockchip/RockUSB 设备，供 RKDevTool 使用。

**本地位置**：

```text
网盘资料\第07章.【立创·泰山派】开发工具\DriverAssitant_v5.11\DriverAssitant_v5.1.1\DriverInstall.exe
```

**安装步骤**：

1. 解压（目录已解压），右键 `DriverInstall.exe`，选择“以管理员身份运行”。
2. 点击 **Install Driver**；若以前安装过异常版本，先点击 **Uninstall Driver**，断开板子后重新安装。
3. 使板子进入 Loader 或 Maskrom，使用 OTG 数据线连接电脑。
4. 打开“设备管理器”核验：不应有黄色感叹号；RKDevTool 的设备状态应变为已发现设备。

**故障排查**：

- RKDevTool 未发现设备：先换数据线、USB 口，再重新进 Loader/Maskrom，最后重装驱动。
- 设备显示为未知设备：不要安装 Android USB driver r13 代替它；优先重装 DriverAssitant。
- 只有串口日志而 RKDevTool 不识别：串口线和 OTG 线是两条不同链路；请接板子 OTG 下载口。

### 3.2 CH340 USB 转串口驱动

**用途**：让 Windows 创建 `COMx` 串口，供 MobaXterm 打开。

**本地包**：`USB转串口驱动-CH340.zip`，包含 `CH340SER.EXE`。

**使用步骤**：

1. 仅当设备管理器没有出现“USB-SERIAL CH340 (COMx)”或有感叹号时，解压并以管理员身份运行安装器。
2. 拔插 USB 转串口模块；在设备管理器中记录 `COM` 号。
3. 打开 MobaXterm 的 Serial 会话，填写该 `COM` 号。

**注意**：常见接线为 GND↔GND、板 TX↔转换器 RX、板 RX↔转换器 TX；**只连接 3.3 V TTL 电平，禁止把 PC 的 RS-232 电平线直接接到板子 UART**。

### 3.3 MobaXterm：串口、SSH、SFTP

**本地程序**：`MobaXterm_Portable_v20.3\MobaXterm_Personal_20.3.exe`，为便携版，不需要安装。

#### A. 串口会话

1. 启动程序，点击 **Session → Serial**。
2. 在 **Serial port** 选择设备管理器中的 `COMx`。
3. 填写波特率；泰山派项目脚本默认 **1500000**，其他镜像常见为 115200，必须以板卡资料/启动日志要求为准。
4. 数据位/校验/停止位通常为 **8N1**，Flow control 选择 **None**。
5. 点击 OK，重启开发板，观察 U-Boot 和 Linux 日志。

常用串口操作：

```sh
# Buildroot / BusyBox 常用命令
ip addr
ip route
cat /proc/cmdline
dmesg | tail -n 100
mount
df -h
```

#### B. SSH + SFTP 会话

1. 确认板子 IP：串口执行 `ip addr`，或从路由器 DHCP 列表查询。
2. **Session → SSH**，填写板端 IP、端口（默认 22）和用户名。
3. 首次连接核对主机指纹；不要在未知网络中盲目接受异常变更的指纹。
4. 登录后，左侧 SFTP 面板可以拖拽文件；或用命令：

```sh
scp ./app root@192.168.1.100:/usr/bin/
ssh root@192.168.1.100
```

**推荐**：将串口会话和 SSH 会话都保存为 Session；串口负责救援和日志，SSH 负责日常开发。

### 3.4 RNDIS（USB 网络）

**用途**：板端把 USB OTG 模拟为网卡，Windows 出现“Remote NDIS Compatible Device”或 USB Ethernet 网卡。它不是串口，也不是 RockUSB 烧录模式。

**使用步骤**：

1. 先确保板端镜像已启用 USB gadget 的 RNDIS 配置；本工具无法“凭空开启”板端 RNDIS。
2. 连接 OTG 后，在设备管理器查看网络适配器。
3. 若显示未知设备，右键“更新驱动程序”→“浏览我的电脑查找驱动程序”，选择本地 `RNDIS驱动.rar` 解压目录中的 `.inf`（若有）；优先让 Windows 使用系统自带 RNDIS 驱动。
4. 在 Windows 和板端为该链路配置同网段 IP，例如电脑 `192.168.7.1/24`、板端 `192.168.7.2/24`，再用 MobaXterm SSH 登录。

## 4. Rockchip 烧录工具

### 4.1 RKDevTool（Windows 图形化烧录，首选）

**用途**：Windows 下识别 RockUSB 设备、下载 Loader、烧录完整 `update.img` 或单分区镜像、擦除/复位设备。

**启动程序**：

```text
05_开发工具\RKDevTool_Release_v2.96_zh\RKDevTool_Release_v2.96\RKDevTool.exe
```

同目录有自带参考：`开发工具使用文档_v1.0.pdf`。

#### A. 烧录完整 `update.img`

这是常规升级的优先方式。

1. 先按 [3.1](#31-driverassitantrockusb-驱动) 安装 RockUSB 驱动。
2. 让板子进入 Loader；无法进入时按板卡手册进入 Maskrom。
3. 打开 RKDevTool，确认底部/设备列表出现 **Loader** 或 **Maskrom**，且不是“No Found RKAndroid rock usb”。
4. 进入 **Upgrade Firmware** 页面，点击 Firmware 右侧的 `...` 选择**确认属于泰山派 RK3566 和当前存储类型**的 `update.img`。
5. 等工具完成文件校验后，点击 **Upgrade**。若你明确需要先清空存储，可选择 **EraseFlash**，但这会删除所有分区数据。
6. 等待进度完成和设备复位；不要在进度条期间拔线。
7. 用串口检查启动日志和系统版本。

#### B. 仅烧录某些分区

适用于已确认分区布局不变，只替换 U-Boot、kernel、rootfs 等场景。

1. 进入 **Download Image** 页面。
2. 按固件工程的配置加载 Loader、参数/分区表和镜像条目；应首先写入与镜像匹配的分区表。
3. 只勾选需要更新的项目，核对分区名称、偏移和镜像文件。
4. 点击 **Run**，完成后 Reset Device 或断电重启。

**禁止事项**：不清楚 `parameter.txt` 或 GPT 分区表是否匹配时，不要混用其他项目的单分区镜像；这会造成镜像写到错误位置或无法启动。

#### C. 常见故障

| 现象 | 处理 |
|---|---|
| 工具找不到设备 | 检查 OTG 线、板子模式、DriverAssitant 和 USB 端口 |
| 只能显示 Maskrom | 通常仍可升级完整固件；先确保选用正确 Loader/`update.img` |
| 校验失败/下载中断 | 重下载并校验镜像哈希，换短数据线和直连 USB |
| 升级成功却无法启动 | 用串口确认是 DDR、Loader、分区表还是 rootfs 问题；不要反复随机烧录 |

### 4.2 `upgrade_tool`（Linux / macOS 命令行）

**本地包**：

```text
Linux_Upgrade_Tool_v1.65.zip
Linux_Upgrade_Tool_v2.1.zip
upgrade_tool_v2.3_mac.zip
```

压缩包内自带《命令行开发工具使用文档.pdf》。该文档明确包含 RK3566，并说明工具支持设备探测、Boot 下载、Loader/分区/整包烧录、按地址读写、擦除、芯片/存储信息读取、多存储和多设备选择。

> 以下命令会写板端存储。先在工具目录执行 `./upgrade_tool ld` 确认连接和模式；文件名仅为示例，不能照抄到不匹配的板型。

```bash
# Linux：使二进制可执行（只需首次）
chmod +x ./upgrade_tool

# 列出 RockUSB 设备；应显示 Loader 或 Maskrom
./upgrade_tool ld

# Maskrom 时下载临时 Boot/DDR Loader：不写入闪存
./upgrade_tool db RK356xMiniLoaderAll.bin

# 写入 Loader（会写入 IDBlock，通常会重启）
./upgrade_tool ul RK356xMiniLoaderAll.bin

# 写入分区表，再写单个/多个分区镜像
./upgrade_tool ul -p parameter.txt
./upgrade_tool ul -k kernel.img
./upgrade_tool ul -u uboot.img -b boot.img
./upgrade_tool ul -vendor vendor.img

# 升级完整固件；-noreset 表示完成后不自动复位
./upgrade_tool uf update.img
./upgrade_tool uf update.img -noreset

# 读取信息
./upgrade_tool rfi       # 存储信息
./upgrade_tool rci       # 芯片 ID
./upgrade_tool pl        # 分区表

# 低级按 LBA 读写（单位通常为扇区；极易损坏数据）
./upgrade_tool wl 0x12000 oem.img
./upgrade_tool rl 0x12000 0x2000 out.img

# 高风险：全部擦除 / 指定扇区擦除
./upgrade_tool ef RK356xMiniLoaderAll.bin
./upgrade_tool el 0 0x2000

# 重启；文档示例中 rd 3 为切至 Maskrom
./upgrade_tool rd
./upgrade_tool rd 3
```

**多设备**：先 `ld` 记录 LocationID，再使用文档所示 `-s <LocationID>`，例如：

```bash
./upgrade_tool -s 100 ul RK356xMiniLoaderAll.bin
```

### 4.3 `rkdeveloptool`（Linux/macOS 开源命令行工具）

**本地源码目录**：`05_开发工具\rkdeveloptool`。它来自 Rockchip 的开源仓库。

#### 编译

```bash
sudo apt update
sudo apt install -y libudev-dev libusb-1.0-0-dev dh-autoreconf pkg-config
cd rkdeveloptool
./autogen.sh             # 或 autoreconf -i
./configure
make
./rkdeveloptool -h
```

如遇 `PKG_CHECK_MODULES(LIBUSB1,libusb-1.0)` 报错，安装 `pkg-config libusb-1.0-0-dev` 后重新执行配置。

可选：为普通用户访问 RockUSB 设备，按仓库内 `99-rk-rockusb.rules` 建立 udev 规则后重新插拔设备；不清楚规则影响时可以先用 `sudo ./rkdeveloptool ...` 验证。

#### 最小使用流程

```bash
# 查看设备
sudo ./rkdeveloptool ld

# Maskrom：下载临时 Loader（不写闪存）
sudo ./rkdeveloptool db RK356xMiniLoaderAll.bin

# 低级写入：0x8000 为扇区地址，仅适用于你已核对偏移的镜像
sudo ./rkdeveloptool wl 0x8000 kernel.img

# 复位
sudo ./rkdeveloptool rd
```

**重要**：`wl` 是按扇区地址写入，不会理解“这是 kernel 分区”。日常优先 `update.img` + RKDevTool/`upgrade_tool`；只有掌握分区表和偏移时才使用 `rkdeveloptool wl`。

### 4.4 FactoryTool（工厂批量烧录）

**本地包**：`FactoryTool-1.71.200.rar`。

**适用场景**：同一型号、多台板子、固定固件的生产线/老化测试烧录。单板开发不建议优先使用它。

**通用操作要点**：

1. 解压到独立目录；先阅读包内 `config.ini`/配置说明。
2. 仅加载经过验证的、与板型一致的量产固件和 Loader。
3. 先只连接一台板做试烧录；检查序列号、分区、启动和版本。
4. 批量前固定 USB 拓扑和端口号，确认每台都进入同一下载模式。
5. 点击 Start/Run 后观察每个端口结果；出现失败时停止批量，先找出线材、电源或镜像问题。

**风险**：配置错误会使同一错误被快速复制到所有板子。没有明确量产需求时，使用 RKDevTool 更可控。

## 5. 固件打包和 SD 卡工具

### 5.1 Linux_Pack_Firmware：生成/解包 `update.img`

**本地包**：`Linux_Pack_Firmware.zip`，解压后核心目录为 `rockdev/`，包含：

- `rk356x-mkupdate.sh`：RK356x 打包脚本；
- `afptool`、`rkImageMaker`：打包组件；
- `orion-package-file`、`sdcard-update-package-file`：打包清单模板；
- `unpack.sh`：解包工具。

压缩包自带说明的流程是：将镜像和 Loader 放入 `rockdev/Image`，修改参数与 `package-file`，运行对应 `mkupdate.sh`，在 `rockdev` 下得到 `update.img`。

```bash
cd Linux_Pack_Firmware/rockdev
mkdir -p Image

# 复制本项目生成且相互匹配的 Loader/parameter/分区镜像到 Image/
# 按实际分区名修改 package-file；不要删改不理解的条目
nano package-file

# RK3566/RK3568 使用对应脚本
chmod +x rk356x-mkupdate.sh
./rk356x-mkupdate.sh

# 生成的 update.img 用 RKDevTool 或 upgrade_tool 烧录
```

解包已有固件：

```bash
cd Linux_Pack_Firmware/rockdev
chmod +x unpack.sh
./unpack.sh /path/to/update.img
# 按工具提示在 output/ 查找解出的文件
```

**核对清单**：芯片为 RK3566；Loader 与 DDR/存储匹配；`parameter.txt` 或 GPT 与所有分区镜像匹配；生成后保留构建提交号和 SHA-256。

### 5.2 SDDiskTool / SD_Firmware_Tool：制作 Rockchip SD 启动/升级卡

**本地包**：`SDDiskTool_v1.7.zip`、`SDDiskTool_cn_v1.74.zip`。包内有 `SD_Firmware_Tool.exe`、`SDBoot.bin`、`sd_boot_config.config`；v1.7 附带“可能导致电脑蓝屏”的警告文本。

**适用场景**：板卡 BSP 明确提供“SD 升级卡/救砖卡”流程时。它不同于把原始 `.img` 直接写卡。

**建议流程**：

1. 先备份 TF 卡全部数据；使用质量可靠的读卡器。
2. 用 SD Card Formatter 格式化卡（见下一节）。
3. 以管理员身份运行 `SD_Firmware_Tool.exe`；正确选择 TF 卡盘符/物理设备。
4. 按板卡资料选择升级固件/镜像和 SD 启动配置；不要混用其他芯片的 `SDBoot.bin`。
5. 开始制作，完成后安全弹出 TF 卡。
6. 断电插卡，按泰山派文档规定的方式启动/触发升级；升级完成后再断电拔卡。

**特别提醒**：目录内 v1.7 已明确提示可能蓝屏。制作前关闭重要工作、保存文件；更推荐 v1.74，仍应先在备用卡验证。

### 5.3 SD Card Formatter：标准格式化 TF 卡

**本地包**：`SDCardFormatterv5_WinEN.zip`，内含安装程序。

1. 插入 TF 卡，先确认 Windows 显示的容量与目标卡一致。
2. 启动 SD Card Formatter，选择正确盘符。
3. 需要更彻底清理旧分区/启动记录时可选择 Overwrite Format；只是常规准备可用 Quick Format。
4. 点击 Format，等待完成后再交给 SDDiskTool 或镜像写入工具。

**警告**：格式化会删除所选卡数据，绝不能按盘符猜测设备。

### 5.4 Win32 Disk Imager：写入原始 `.img`

**本地包**：`win32diskimager-1.0.0-install.exe.zip`。

**只在镜像提供方明确给出“raw disk image / `.img` 直接写卡”时使用**：

1. 解压安装器并安装，建议以管理员身份启动。
2. Image File 选择目标 `.img`。
3. Device 选择 TF 卡对应盘符，反复按容量确认。
4. 点击 **Write**，确认警告；完成后安全弹出。
5. 若要备份卡，可选择保存文件后点击 **Read**。

不要用它写 `update.img`，也不要把 Windows 系统盘误选为目标设备。

## 6. Android 调试工具

> 泰山派若运行 Buildroot/Linux 而没有 `adbd`，`adb` 和 `scrcpy` 都不会连接成功。这不是工具故障；请改用串口/SSH/RNDIS。

### 6.1 Android platform-tools：`adb` 与 `fastboot`

**本地包**：`platform-tools_r33.0.3-windows.zip`、`platform-tools_r33.0.3-linux.zip`。

#### A. ADB

Windows PowerShell 示例：

```powershell
cd 'E:\...\platform-tools'
.\adb.exe version
.\adb.exe devices -l
.\adb.exe shell
.\adb.exe push .\app /data/local/tmp/
.\adb.exe pull /sdcard/log.txt .\log.txt
.\adb.exe logcat
.\adb.exe reboot
```

- 手机上的/板端 Android 系统必须开启开发者选项与 USB 调试，并在设备侧接受 RSA 授权。
- `adb devices` 状态为 `unauthorized` 时在设备屏幕确认授权；`offline` 时重启 `adbd` 或重新插线。
- `adb install` 只适用于 Android APK；不能用于 Buildroot rootfs。

#### B. Fastboot

```powershell
.\adb.exe reboot bootloader
.\fastboot.exe devices
.\fastboot.exe getvar product
# 仅在设备厂商文档明确支持时才执行：
.\fastboot.exe flash boot boot.img
.\fastboot.exe reboot
```

Fastboot 与 RockUSB 是不同协议；RK3566 板处于 Loader/Maskrom 时应使用 RKDevTool/`upgrade_tool`，不是 `fastboot`。

### 6.2 scrcpy：Android 投屏和控制

**本地包**：`scrcpy-win64-v2.3.1.zip`。该包自带 `adb.exe`，但建议不要让多个不同目录的 ADB 同时常驻运行。

1. 先用 `adb devices` 确认 Android 设备为 `device` 状态。
2. 解压 scrcpy，双击 `open_a_terminal_here.bat` 打开终端。
3. 执行：

```bat
scrcpy
scrcpy --no-audio --record=record.mkv
scrcpy --turn-screen-off --stay-awake
scrcpy --serial <设备序列号>
```

- `scrcpy-noconsole.vbs` 可无控制台启动，但报错不可见；首次排障应使用终端方式。
- 多设备时先 `adb devices -l`，再使用 `--serial` 指定设备。

## 7. 安全启动与不可逆工具

### 7.1 SecureBootTool：固件签名

**本地包**：`SecureBootTool_v2.2.zip`，内有 `SecureBootTool_UserManual.pdf`。

其自带手册说明：工具用于对固件各级启动代码签名；可生成 RSA 密钥对、转换 bin/PEM 密钥、签名 `update.img`、Loader 和 DDR 测试文件。不同芯片/安全级别对应不同密钥与签名方案。

**只有在已确定量产 Secure Boot 方案时才可按以下流程操作**：

1. 明确芯片、BootROM 安全方案、密钥长度、是否使用 PSS、摘要字节序。
2. 在离线、受控环境生成密钥；私钥不得放在项目仓库、网盘或聊天记录中。
3. 在工具中选正确芯片，加载经审批的私钥和公钥。
4. 先对测试 `update.img` 执行 Sign Firmware，在**未熔丝锁定的测试板**上验证启动。
5. 通过后才进入生产签名/烧录流程；保留密钥版本、固件哈希和签名日志。

**不要做**：把其他项目的密钥直接复用；凭界面猜芯片；签名后不测试就写 eFuse。

### 7.2 EfuseTool：一次性熔丝

**本地包**：`EfuseTool_v1.42.zip`。

eFuse 是芯片的一次性可编程区域，可能承载安全启动公钥哈希、调试禁用位或安全状态。写错后一般无法恢复。

**默认策略**：研发样机和课程开发阶段不使用。只有安全负责人提供了经过评审的 eFuse 映射、密钥公钥哈希、烧写顺序、回读校验和失效处置方案时，才在专用量产工位执行。

执行前至少要完成：

- 双人复核芯片型号、烧写字段、目标板序列号；
- 在未锁定的样机完成 SecureBoot 启动验证；
- 备份日志，记录烧写前后读回值；
- 确认可承受该板永久报废的后果。

### 8.1 7-Zip

### 8.2 WSL2 内核更新包

**本地包**：`wsl_update_x64.zip`，包含 `wsl_update_x64.msi`。

**用途**：更新 Windows 的 WSL2 Linux 内核，便于在 Windows 主机上编译/运行 Linux 工具；它不会更新开发板的内核。

优先使用管理员 PowerShell：

```powershell

```

只有在 Windows/WSL 明确提示需要手工内核 MSI 时，再解压并运行本地 `wsl_update_x64.msi`；安装后执行 `wsl --shutdown` 再重新打开 Linux 发行版。

### 8.3 `repo` 多仓库工具

**本地文件**：`repo工具\2025-07-07\repo`（无扩展名 Python 脚本）。

`repo` 构建在 Git 之上，用 manifest 同时管理多个仓库，常见于 Android/Rockchip 源码树。它**不替代 Git**。

Linux 使用示例：

```bash
mkdir -p ~/bin
cp /path/to/repo ~/bin/repo
chmod a+rx ~/bin/repo
export PATH="$HOME/bin:$PATH"

# 以下 URL、分支、manifest 名必须由 BSP/供应商提供
mkdir rk-source && cd rk-source
repo init -u <manifest-url> -b <branch> -m <manifest.xml>
repo sync -c -j$(nproc)
repo status
repo forall -c 'git status --short'
```

不要凭空填写 manifest URL；当前项目如果只是单个 Git 仓库，不需要引入 `repo`。

## 10. 推荐工作流

### 10.1 第一次烧录 / 救砖

1. 安装 DriverAssitant。
2. 同时连接串口（MobaXterm）以保留日志通道。
3. 按板卡资料进入 Loader；失败则进入 Maskrom。
4. 用 RKDevTool v2.96 烧录与泰山派 RK3566 对应的完整 `update.img`。
5. 重启后看串口，确认 U-Boot、kernel、rootfs 都正常。
6. 系统有网络后再用 SSH 进行日常操作。

### 10.2 只改了 kernel/rootfs 后升级

1. 先确认固件工程没有改变 Loader、分区表和分区偏移。
2. 如已有可靠 `update.img`，仍优先整包升级。
3. 只有在确认分区名与布局一致时，才在 RKDevTool 的 Download Image 或 `upgrade_tool ul` 中更新单分区。
4. 保留上一版可启动的完整固件和串口日志。

### 10.3 Android 镜像调试

1. 串口确认 Android 已启动；板端开启 USB debugging。
2. 使用 `adb devices -l` 连接。
3. 需要画面和输入控制时运行 scrcpy。
4. 需要底层恢复/刷机时退出 ADB 思路，改用 RockUSB + RKDevTool。
