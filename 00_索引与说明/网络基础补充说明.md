# 网络基础补充说明（泰山派 Buildroot）

> 适用：当前 Buildroot + wlan0  
> 目的：把“能连上 Wi-Fi”变成“真正理解发生了什么”  
> 相关：[`启动流程-从通电到联网.md`](启动流程-从通电到联网.md)

---

## 1. 先把网络想成寄快递

上网时，数据像快递包裹：

```text
你的板子（发件人）
  → 路由器（小区门卫/中转站）
  → 互联网
  → 目标服务器（收件人）
```

要寄出包裹，你至少需要：

| 东西 | 现实类比 | 板子上对应 |
|---|---|---|
| 自己的地址 | 自己家门牌号 | IP，如 `192.168.0.105` |
| 小区出口 | 物业/门卫 | 网关，如 `192.168.0.1` |
| 对方地址 | 对方门牌号 | 目标 IP，如 `8.8.8.8` |
| 名字查号 | 电话簿 | DNS，把 `baidu.com` 查成 IP |

---

## 2. 四层，不要一次全混在一起

### 第 1 层：网卡在不在？

```bash
ip addr
ifconfig wlan0
```

看到 `wlan0`，只说明：

```text
Wi-Fi 网卡设备存在
```

还不能说明已经连上 Wi-Fi，更不能说明能上网。

---

### 第 2 层：网卡开了没有？

```text
wlan0: UP
```

只说明：

```text
接口已启用，像“Wi-Fi 开关打开了”
```

此时可能仍然：

- 没有连上热点
- 没有 IP
- 不能上网

---

### 第 3 层：有没有连上热点？

```bash
wifi-connect.sh ccccc2.4g '<密码>'
```

成功日志类似：

```text
Link UP
connection succeeded
ssid "ccccc2.4g"
```

这只说明：

```text
无线链路通了
板子已经和路由器“对上暗号”
```

还差最关键的一步：**拿到自己的门牌号（IP）**。

---

### 第 4 层：有没有拿到 IP？

```bash
udhcpc -i wlan0 -n -q
ip addr show wlan0
```

成功后会看到：

```text
inet 192.168.0.105/24
```

这时板子才真正“有地址”，可以在局域网里被找到。

你当时的结果：

```text
IP：192.168.0.105/24
网关：192.168.0.1
DNS：192.168.0.1
```

含义：

```text
板子地址：192.168.0.105
这个小局域网范围：192.168.0.x
出小区要找：192.168.0.1（路由器）
查域名要问：192.168.0.1（也常由路由器提供 DNS）
```

---

## 3. `/24` 是什么意思？

```text
192.168.0.105/24
```

可以先记成：

```text
前 3 段相同的，都算同一局域网
```

也就是：

```text
192.168.0.1
192.168.0.2
...
192.168.0.105
...
192.168.0.254
```

这些通常都属于同一个“家庭局域网”。

所以：

- 板子：`192.168.0.105`
- 路由器：`192.168.0.1`
- 你的电脑如果也连同一 Wi-Fi，多半也是 `192.168.0.x`

---

## 4. 网关是什么？

网关 = 出局域网的大门。

```text
板子要访问外网
  → 先把包交给网关 192.168.0.1
  → 再由路由器转发到互联网
```

所以：

```bash
ping 192.168.0.1
```

测的是：

```text
板子到路由器通不通
```

```bash
ping 8.8.8.8
```

测的是：

```text
路由器后面的外网通不通
```

---

## 5. DNS 是什么？再讲一遍

人记名字：

```text
baidu.com
```

机器通信用数字：

```text
110.242.74.102
```

DNS 就是查号台：

```text
问：baidu.com 是多少？
答：110.242.74.102
```

### 为什么两个 ping 意义不同？

```bash
ping 8.8.8.8
```

你直接给门牌号，不查电话簿。  
验证：

```text
外网 IP 是否可达
```

```bash
ping baidu.com
```

必须先查电话簿，再访问。  
验证：

```text
DNS + 外网
```

### 常见组合

| 现象 | 通常含义 |
|---|---|
| `8.8.8.8` 不通 | 网络链路/路由可能有问题 |
| `8.8.8.8` 通，`baidu.com` 不通 | 更像 DNS 问题 |
| 两者都通 | IP 和 DNS 都正常 |

## 6. 你已经实际走过的完整链路

```text
1. 驱动加载，出现 wlan0
2. wlan0 UP（网卡打开）
3. 扫描到 ccccc2.4g
4. wifi-connect 关联成功（Link UP）
5. udhcpc 拿到 192.168.0.105
6. ping 本机 / 外网 IP / 域名 成功
```

对应“快递模型”：

```text
有车（网卡）
  → 发动了（UP）
  → 找到了目的小区门口并核对身份（连上 Wi-Fi）
  → 拿到了自己门牌号（IP）
  → 知道出小区找谁（网关）
  → 会查地名（DNS）
  → 真正寄出包裹（ping/SSH）
```

---

## 7. 现在最容易混的 3 句话

### 混点 A

```text
有 wlan0  ≠  已联网
```

### 混点 B

```text
Link UP  ≠  有 IP
```

### 混点 C

```text
能 ping 通 IP  ≠  域名一定能通
```

把这三句记住，网络排错就清楚很多。

---

## 8. 以后排错顺序（背这个）

```text
1. 有没有 wlan0？
2. wlan0 是否 UP？
3. 是否 Link UP / 已连接 SSID？
4. 有没有 inet IP？
5. 能否 ping 网关？
6. 能否 ping 8.8.8.8？
7. 能否 ping baidu.com？
```

卡在哪一层，就只查那一层，不要一上来重装系统。

## 9. 和 SSH 的关系

SSH 登录要求：

```text
板子已有 IP
电脑和板子在同一局域网（或路由可达）
板子 sshd 服务已启动
```

你当前已具备：

```text
板子 IP：192.168.0.105
sshd：已启动（启动日志有 Starting sshd: OK）
```

所以下一步可以从电脑：

```text
ssh root@192.168.0.105
```

尝试登录。

---

## 10. 一句话总结

网络不是一步完成的，而是：

```text
网卡出现
 → 网卡打开
 → 连上 Wi-Fi
 → 拿到 IP
 → 会走网关
 → 会查 DNS
 → 应用才能真正上网
```

你现在已经走完这条链；剩下的是把每一层的含义记牢，避免以后只机械执行命令。

## 11. SSH 已打通后的备注（2026-07-24）

当前已经可以从电脑：

```text
ssh root@<板子当前IP>
```

登录 Buildroot。

请记住：

```text
串口 = 不依赖网络的“维修通道”
SSH  = 依赖网络的“日常开发通道”
```

重启后如果 SSH 连不上，按这个顺序查：

```text
1. 串口是否还能进系统？
2. wlan0 是否还连着 Wi-Fi？
3. 当前 IP 是否变化？
4. 22 端口是否仍在监听？
5. 用户名/密码是否正确？
```
