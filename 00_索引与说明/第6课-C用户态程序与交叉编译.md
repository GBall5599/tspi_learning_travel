# 第 6 课：第一个 C 用户态程序与 AArch64 交叉编译

> 完成日期：2026-07-29
> 开发主机：Ubuntu 22.04.5 LTS x86_64（VMware 桥接网络）
> 目标板：LCKFB-TSPI-RK3566-2G-16G，Buildroot 2024.02 + Linux 6.1.141 aarch64

## 1. 本课目标

完成第一个从 Ubuntu 开发主机到 RK3566 开发板的 C 程序闭环：

```text
编写 hello.c
  → 使用 AArch64 交叉编译器编译
  → 检查 ELF 架构和链接方式
  → 通过 SCP 上传到 /userdata
  → 在 RK3566 上运行
  → 检查退出码
```

## 2. 为什么需要交叉编译

开发主机与开发板的 CPU 架构不同：

| 环境 | 架构 | 作用 |
|---|---|---|
| Ubuntu 22.04.5 虚拟机 | x86_64 | 编写、编译和上传程序 |
| 泰山派 RK3566 | AArch64 / ARM64 | 运行目标程序 |

Ubuntu 本机的普通 `gcc` 默认生成 x86-64 程序，RK3566 无法执行。使用：

```bash
aarch64-linux-gnu-gcc
```

可在 x86-64 Ubuntu 上生成适用于 ARM64 Linux 的程序，这就是交叉编译。

## 3. 最小 C 源程序

Ubuntu 工作目录：

```text
~/workspace/rk3566-lesson6
```

源文件 `hello.c`：

```c
#include <stdio.h>

int main(void)
{
    printf("hello from RK3566!\n");
    return 0;
}
```

说明：

- `#include <stdio.h>`：引入声明 `printf()` 的标准输入输出头文件；
- `int main(void)`：C 程序入口，明确表示不接收参数；
- `printf()`：向标准输出写入文本；
- `return 0`：向 shell 返回成功退出码 0。

## 4. 交叉编译

执行：

```bash
aarch64-linux-gnu-gcc -std=c11 -Wall -Wextra -O0 -static -o hello hello.c
```

本次无报错、无警告，并生成：

```text
hello
hello.c
```

参数含义：

| 参数 | 作用 |
|---|---|
| `-std=c11` | 使用 C11 语言标准 |
| `-Wall -Wextra` | 开启常用附加警告 |
| `-O0` | 关闭优化，便于初学与后续调试 |
| `-static` | 静态链接 C 运行库，避免首次实验依赖目标机动态链接器/库版本 |
| `-o hello` | 指定输出可执行文件名 |

## 5. 检查 ELF 产物

Ubuntu 执行：

```bash
file hello
```

结果：

```text
hello: ELF 64-bit LSB executable, ARM aarch64, version 1 (GNU/Linux), statically linked, BuildID[sha1]=f78d71ce0b64f8f7c8fa8a4ddb064f6ad6c406a9, for GNU/Linux 3.7.0, not stripped
```

关键结论：

- `ELF 64-bit`：Linux 64 位可执行文件；
- `ARM aarch64`：面向 RK3566 的 ARM64 指令集；
- `statically linked`：静态链接；
- `not stripped`：保留符号信息，适合初期分析与调试。

反向验证在 Ubuntu 上运行：

```bash
./hello
```

结果：

```text
bash: ./hello: cannot execute binary file: Exec format error
```

这是预期结果。Ubuntu 内核是 x86-64，无法执行 AArch64 指令；该现象反而证明该程序不是误编译出的本机程序。

## 6. 通过 SCP 上传

先确认 Ubuntu 可访问开发板：

```bash
ping -c 3 192.168.30.227
```

结果为 `3 received`、`0% packet loss`。

上传命令：

```bash
scp hello root@192.168.30.227:/userdata/hello_c
```

传输成功：

```text
hello  100%  626KB  131.4KB/s  00:04
```

`scp`（Secure Copy）通过 SSH 的认证与加密连接传输文件。本次路径含义为：

```text
Ubuntu 源文件 hello
  → SSH/Dropbear
  → RK3566 持久化路径 /userdata/hello_c
```

## 7. RK3566 上运行与退出码

登录开发板：

```bash
ssh root@192.168.30.227
```

检查上传后的文件：

```sh
ls -l /userdata/hello_c
```

结果：

```text
-rwx------ 1 root root 641000 Jul 29 16:21 /userdata/hello_c
```

`x` 权限表示 root 可以直接执行该文件；`/userdata` 是持久化数据分区。

运行：

```sh
/userdata/hello_c
```

输出：

```text
hello from RK3566!
```

紧接着执行：

```sh
echo $?
```

结果：

```text
0
```

退出码 0 表示程序正常结束。
