# 第 3 课：第一个用户态程序

> 完成日期：2026-07-25  
> 板卡：LCKFB-TSPI-RK3566-2G-16G  
> 系统：Buildroot 2024.02 + Linux 6.1.141  
> 运行位置：`/userdata/hello.sh`

## 1. 本课目标

完成最小的用户态开发闭环：

```text
创建文件
  → 写入脚本
  → 使用 shell 解释执行
  → 添加执行权限
  → 直接运行
  → 查看退出状态码
  → 接收命令行参数
```

本课使用 Shell 脚本，不要求板端具备 GCC，也不涉及内核驱动或设备树。

## 2. 最终程序

当前 `/userdata/hello.sh` 的内容为：

```sh
#!/bin/sh
echo "Hello from RK3566!"
echo "current user: $(id -un)"
echo "current pwd:  $(pwd)"
echo "current time: $(date)"
echo "argument count: $#"
echo "first argument: $1"
```

说明：

- `#!/bin/sh`：指定由 `/bin/sh` 解释；
- `$(id -un)`：执行命令并把结果嵌入输出；
- `$(pwd)`：显示当前目录；
- `$(date)`：显示板端当前时间；
- `$#`：命令行参数总数量；
- `$1`：第一个命令行参数。

## 3. 运行方式

### 3.1 使用解释器运行

```sh
sh /userdata/hello.sh
```

这种方式由 `sh` 读取脚本，因此文件暂时没有执行权限也可以运行。

### 3.2 添加执行权限

```sh
chmod +x /userdata/hello.sh
```

权限从类似下面的状态：

```text
-rw-r--r--
```

变成：

```text
-rwxr-xr-x
```

其中 `x` 表示执行权限。

### 3.3 直接运行

```sh
cd /userdata
./hello.sh
```

`./` 表示当前目录。Linux 默认不会因为文件位于当前目录，就自动搜索并执行它。

## 4. 退出状态码

执行成功后立即检查：

```sh
./hello.sh
echo "exit code=$?"
```

结果为：

```text
exit code=0
```

约定上：

```text
0       成功
非 0    失败或异常
```

例如：

```sh
ls /not_exist
echo "exit code=$?"
```

由于路径不存在，`ls` 返回了非零状态码 `2`。

注意：`$?` 表示上一条命令的状态码，应当及时检查；执行其他命令后它会被更新。

## 5. 命令行参数

运行：

```sh
./hello.sh lesson3
```

输出：

```text
argument count: 1
first argument: lesson3
```

运行多个参数：

```sh
./hello.sh one two three
```

输出：

```text
argument count: 3
first argument: one
```

脚本已经收到三个参数，但当前只显示 `$1`。后续可以继续学习 `$2`、`$3`、`$@` 和参数循环。

## 7. MobaXterm 注意事项

本次实践发现，MobaXterm 20.3 向串口粘贴多行内容时，可能破坏换行和转义字符，曾把 `\necho` 粘贴成了错误的 `/necho`。

因此后续串口操作遵守：

- 每次只输入一条命令；
- 不使用多行 `cat <<EOF`；
- 不把包含 `\n` 的长 `printf` 命令直接粘贴到串口；
- 写文件时优先使用 `vi`，或使用简单的单行 `echo '...' >> 文件`。

## 8. 与内核、系统服务的区别

`hello.sh` 是用户态程序：

```text
由 shell 启动
运行在用户空间
可以访问普通文件和系统命令
结束后返回退出状态码
```

它不是：

- 内核模块；
- 设备树；
- 系统服务；
- 驱动程序。

本课的重点是先建立“程序可以被创建、执行、传参并返回结果”的基本感觉。
