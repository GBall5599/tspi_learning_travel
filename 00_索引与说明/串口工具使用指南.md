# 串口工具使用指南（泰山派 RK3566）

> 适用板卡：LCKFB-TSPI-RK3566-2G-16G  
> 当前系统：Buildroot 2024.02 + Linux 6.1.141  
> 本机已确认串口：`COM9`  
> 串口参数：`1500000 8N1`

## 1. 串口和 SSH 的区别

- **SSH**：通过网络连接板子，需要 Wi-Fi 已经联网并且知道当前 IP。
- **串口**：电脑通过 USB 转串口线直接连接板子，不需要 Wi-Fi、IP 或 SSH 服务。

所以这次重启后 SSH 断开，要先用串口进入板子检查启动状态。

## 2. 硬件连接

泰山派 Debug 接口是 GH1.25 4P。实际调试只需要三根线：

| 泰山派 Debug | USB 转串口 |
|---|---|
| GND | GND |
| TX | RX |
| RX | TX |

**不要连接 VCC。** 泰山派 Debug 口的 VCC 与板上 5V 有连接，USB 转串口一般只使用信号线和地线即可。

连接后给开发板正常供电，再在电脑上确认串口号。当前电脑检测到的是 `COM9`。

## 3. 当前使用的工具

项目之前使用的是 PowerShell 串口脚本：

```text
E:\Embed_Proj\tools\serial_monitor.ps1
```

它支持：

- 查看可用 COM 口；
- 读取串口输出；
- 启动时向板子发送一条命令；
- 将输出保存为日志。

### 重要限制

这个脚本目前**不是完整的交互式终端**：启动后不能像 SSH 那样随时输入任意命令。每发送一条命令，都重新运行一次脚本的 `-Send` 参数。

## 4. 查看电脑识别到哪些串口

在 Windows PowerShell 中执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File "E:\Embed_Proj\tools\serial_monitor.ps1" -List
```

预期输出：

```text
COM9
```

如果没有 `COM9`：

1. 检查 USB 转串口线和驱动；
2. 拔插 USB 转串口模块；
3. 打开 Windows 设备管理器，查看“端口（COM 和 LPT）”；
4. 将命令中的 `COM9` 换成设备管理器显示的端口号。

## 5. 只读取串口输出

### 读取 30 秒

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File "E:\Embed_Proj\tools\serial_monitor.ps1" `
  -Port COM9 -BaudRate 1500000 -Seconds 30 -NoClear
```

### 一直读取，按 Ctrl+C 退出

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File "E:\Embed_Proj\tools\serial_monitor.ps1" `
  -Port COM9 -BaudRate 1500000 -NoClear
```

说明：

- `-Port COM9`：使用 COM9；
- `-BaudRate 1500000`：泰山派使用 1500000 波特率；
- `-Seconds 30`：读取 30 秒；
- `-NoClear`：不清空已经收到的串口数据；
- `Ctrl+C`：停止当前串口读取。

如果看到乱码，优先检查波特率是否为 `1500000`，不要改成常见的 `115200`。

## 6. 查看开机日志

如果要观察完整启动过程：

1. 先运行下面的命令；
2. 再按开发板复位键，或者重新给开发板上电；
3. 等待日志出现 `root@taishanpi:/#`；
4. 按 `Ctrl+C` 停止读取。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File "E:\Embed_Proj\tools\serial_monitor.ps1" `
  -Port COM9 -BaudRate 1500000 -NoClear `
  -LogFile "E:\Embed_Proj\tspi_rk3566\串口-本次启动日志.txt"
```

必须先打开串口读取，再重启板子，否则重启早期的 DDR、U-Boot 和 Linux 日志可能已经错过。

## 7. 通过串口发送一条 Linux 命令

脚本会打开串口，等待约 1.8 秒，然后发送 `-Send` 后面的命令，并读取输出。

例如查看系统是否启动：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File "E:\Embed_Proj\tools\serial_monitor.ps1" `
  -Port COM9 -BaudRate 1500000 -NoClear `
  -Send "uname -a" -Seconds 8
```

查看当前 Wi-Fi 状态：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File "E:\Embed_Proj\tools\serial_monitor.ps1" `
  -Port COM9 -BaudRate 1500000 -NoClear `
  -Send "ip -4 addr show wlan0; ip route" -Seconds 10
```

注意：`-Send` 发送的命令必须是一行。多条命令可以使用分号连接，例如：

```text
ip -4 addr show wlan0; ip route; ping -c 2 192.168.0.1
```

## 8. 本次第 2 课现在要执行的命令

开发板已经重启，先不要改配置，先执行下面这条检查命令：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File "E:\Embed_Proj\tools\serial_monitor.ps1" `
  -Port COM9 -BaudRate 1500000 -NoClear `
  -Send "echo --- IP ---; ip -4 addr show wlan0; echo --- ROUTE ---; ip route; echo --- FILES ---; ls -l /etc/wpa_supplicant.conf /tmp/wpa_supplicant.conf 2>/dev/null; echo --- ETC CONFIG ---; if [ -f /etc/wpa_supplicant.conf ]; then sed 's/psk=.*/psk=\"******\"/' /etc/wpa_supplicant.conf; fi; echo --- TMP CONFIG ---; if [ -f /tmp/wpa_supplicant.conf ]; then sed 's/psk=.*/psk=\"******\"/' /tmp/wpa_supplicant.conf; fi" `
  -Seconds 15
```

这条命令不会显示真实 Wi-Fi 密码，只会显示：

- `wlan0` 有没有 IPv4 地址；
- 默认路由是否存在；
- `/etc` 和 `/tmp` 中的配置文件是否存在；
- SSID 和被打码后的密码字段。

把输出发回时，确认其中没有真实密码即可。

## 9. 发送重启命令

只有在配置修改并且手动验证成功后，才使用：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File "E:\Embed_Proj\tools\serial_monitor.ps1" `
  -Port COM9 -BaudRate 1500000 -NoClear `
  -Send "sync; reboot" -Seconds 25
```

重启验证时，建议先用第 6 节的“读取开机日志”命令打开串口，再执行重启命令。

## 10. 常见问题

### 没有任何输出

- 确认板子已经供电；
- 确认使用的是 Debug 串口，不是普通 UART；
- 确认 GND/TX/RX 接线正确；
- 确认 COM 号正确；
- 确认波特率是 `1500000`；
- 按一次复位键观察是否出现启动日志。

### 出现乱码

通常是波特率错误。泰山派当前串口参数为：

```text
1500000，8 数据位，无校验，1 停止位（8N1）
```

### 看到日志但不能执行命令

确认已经进入 shell 提示符：

```text
root@taishanpi:/#
```

如果还在 Linux 启动日志阶段，等待启动完成。脚本发送命令时，板子必须已经能接受 shell 命令。

### SSH 断开是否代表板子死机

不一定。SSH 断开可能只是：

- Wi-Fi 尚未连接；
- DHCP 尚未拿到 IP；
- 重启后 IP 发生变化；
- Dropbear 还没有启动。

串口可以直接区分“系统没启动”和“系统已启动但网络没起来”。

## 11. 第 2 课：复杂串口命令的安全执行方式

Windows PowerShell 的双引号不能使用 Linux/C 风格的 `\"` 转义；复杂命令直接粘贴时，容易被 PowerShell 提前拆开。

第 2 课创建开机脚本时，请使用项目内已经准备好的辅助脚本，而不要手工粘贴超长命令：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "E:\Embed_Proj\tspi_rk3566\05_开发工具\第2课-创建WiFi自动脚本.ps1"
```

该辅助脚本：

- 使用当前确认的 `COM9` 和 `1500000 8N1`；
- 只创建 `/etc/init.d/S45wifi-auto`；
- 不包含、不读取、也不输出 Wi-Fi 密码；
- 完成后显示脚本权限与内容。

若只想预览、不发送到开发板，可添加 `-DryRun`：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "E:\Embed_Proj\tspi_rk3566\05_开发工具\第2课-创建WiFi自动脚本.ps1" -DryRun
```

## 12. 需要 vi 时使用交互式 MobaXterm

`serial_monitor.ps1` 只能发送一条命令，不能持续转发键盘输入，因此不适合交互式 `vi`。

项目中已有便携版 MobaXterm：

```text
网盘资料\第07章.【立创·泰山派】开发工具\MobaXterm_Portable_v20.3.zip
```

解压后运行：

```text
MobaXterm_Personal_20.3.exe
```

创建会话：

1. `Session` → `Serial`
2. Serial port：`COM9`
3. Speed：`1500000`
4. Flow control：`None`
5. 连接后看到 `root@taishanpi:~#` 即可输入命令

使用 `vi`：

```text
i       进入编辑模式
Esc     退出编辑模式
:wq     保存退出
:q!     放弃修改并退出
```

因此：

```text
固定单行命令：serial_monitor.ps1
交互式编辑/vi：MobaXterm Serial
```
