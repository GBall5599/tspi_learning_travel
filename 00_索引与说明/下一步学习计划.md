## 2. 总原则与安全边界

继续遵循：

```text
先明确目标
→ 补齐必要概念
→ 判断系统层次
→ 选择一条命令或一次改动
→ 观察结果
→ 用自己的话复述
→ 总结并写入文档
```

实操规则：

- 每次只执行一个可解释、可观察的动作；
- 新概念先解释，再执行命令；
- 修改前记录原状态、原始文件和恢复方式；
- 修改设备树、镜像、网络或启动配置时，串口必须可用；
- 不直接编辑 `/proc/device-tree`；它是运行时只读视图；
- 未确认硬件接线、供电、pinmux 和面板时序前，不导出未知 GPIO、不改背光；
- SDK、内核源码和构建目录只放在 Ubuntu 的 ext4 文件系统中，不在 Windows NTFS 共享目录直接构建；
- 每一课结束时提交学习记录，至少包含目的、命令、现象、结论、恢复点和下一步。

## 4. 第 8 课：显示与 3.1 寸 MIPI 屏——只读盘点

### 4.1 目标

先理解当前 Buildroot 的显示链路：

```text
显示控制器（VOP）
  → HDMI 或 MIPI DSI
  → 外部显示设备（显示器 / MIPI 面板）
  → 背光、触摸
  → framebuffer / DRM 用户态接口
```

### 4.2 需要补齐的概念

- VOP：Rockchip 显示输出处理器；
- HDMI：常见外接显示接口；
- MIPI DSI：面向嵌入式面板的高速串行显示接口；
- panel：具体显示面板；
- backlight：背光控制节点或设备；
- touch：触摸控制器及其 input 设备；
- framebuffer / DRM：内核向用户态提供的显示接口。

### 4.3 实操范围

只读盘点以下内容：

- `/sys/class/graphics`、`/dev/fb*`、`/sys/class/drm` 的实际状态；
- 运行时设备树中的 `display-subsystem`、VOP、HDMI、MIPI DSI、panel、backlight、touch 节点；
- 启动日志中显示子系统、面板、背光和触摸相关信息；
- 当前 Buildroot 到底使用 HDMI、MIPI，还是显示接口尚未启用。

### 4.4 禁止动作

- 不改 DTS / DTSI；
- 不烧录 Debian MIPI 镜像；
- 不改未知 GPIO；
- 不手动操作未知背光 GPIO；
- 不根据单个设备树节点存在就断言驱动已成功工作。

### 4.5 成功标准

- 能定位 VOP、HDMI、MIPI DSI 和显示子系统节点；
- 能区分显示控制器节点与具体面板节点；
- 能说明 framebuffer / DRM 接口是否真实存在；
- 能说明 HDMI 与 MIPI 面板验证路径的差异；
- 不改变系统和未知硬件状态。

预计投入：1～2 次学习会话。

## 5. 第 9 课：官方 MIPI Debian 镜像——建立屏幕工作基线

### 5.1 目标

使用本地已下载的官方 Debian 12 kernel 6.1 3.1 寸 MIPI 镜像，确认屏幕、背光和触摸在官方基线中的工作状态。

### 5.2 前置条件

- 第 8 课的只读盘点已完成；
- 已记录当前 Buildroot 镜像、串口参数和网络配置；
- 已明确烧录和恢复 Buildroot 的流程；
- 串口可用，可在图形输出异常时观察启动日志。

### 5.3 验证清单

- 系统是否正常启动；
- 屏幕是否点亮，分辨率、方向和颜色是否正确；
- 背光是否正常；
- 触摸是否识别为 input 设备；
- 网络、SSH 和串口是否可用；
- 记录与当前 Buildroot 在设备树、显示接口和日志上的差异。

### 5.4 成功标准

建立“官方镜像 + 已知硬件 + 已知接线”的工作基线，能够区分硬件问题、当前 Buildroot 配置问题与驱动 / 设备树问题。

预计投入：1～2 次学习会话。

预计投入：2～3 次学习会话。

## 7. 第 11 课：第一次受控设备树修改

### 7.1 实验选择

不直接修改屏幕时序。先选择影响小、可验证、可回退的已知属性，例如 RGB LED 的默认 trigger：

```text
linux,default-trigger：timer
  → heartbeat 或 none
```

### 7.2 标准流程

```text
定位 DTS / DTSI 源码
  → 备份原始文件和可启动镜像
  → 仅修改一个已知属性
  → 编译 DTB
  → 部署或重新打包
  → 串口启动观察
  → /proc/device-tree 验证
  → /sys/class/leds 验证
  → 记录结果并保留回退路径
```

### 7.3 成功标准

完成一次可复现的“源码 → DTB → 启动 → 运行时验证 → 回退”闭环。

预计投入：2～3 次学习会话。

## 8. 第 12 课：内核模块、驱动与排障基础

### 8.1 建议顺序

1. 用匹配的 SDK / 内核配置构建最小 `hello.ko`；
2. 学习模块加载、卸载和 `dmesg` 日志观察；
3. 区分用户态 C 程序与内核模块的运行位置和职责；
4. 进入 GPIO、input、I2C 或触摸相关驱动框架；
5. 学习驱动排障链路：

```text
设备树节点
  → compatible 匹配
  → 驱动 probe
  → dmesg
  → /sys 或 /dev 用户态接口
```

### 8.2 成功标准

能够使用日志和用户态接口判断“节点存在但设备未出现”时大致应该检查哪一层，而不是只反复修改 DTS。

预计投入：2～3 次学习会话。
