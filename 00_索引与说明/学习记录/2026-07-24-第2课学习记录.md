## 一、课程结果

第 2 课已完成。目标是：开发板重启后无需手动执行 `wifi-connect.sh`，自动连接 Wi-Fi、自动获取 IP，并恢复 SSH。

最终验证结果：

- Wi-Fi：`ccccc2.4g`
- 重启后 IP：`192.168.0.106/24`
- 网关：`192.168.0.1`
- 网关 Ping：2/2 成功，0% 丢包
- SSH：`ssh root@192.168.0.106` 登录成功
- SSH 服务：Dropbear 启动成功

启动日志中的关键证据：

```text
Starting wifi-auto
connection succeeded
udhcpc: lease of 192.168.0.106 obtained from 192.168.0.1
wifi-auto: OK
Starting dropbear sshd: OK
```

## 二、实际完成的系统改动

### 1. 持久化 Wi-Fi 配置

原先 `wifi-connect.sh` 使用：

```text
/tmp/wpa_supplicant.conf
```

由于 `/tmp` 重启后会清空，所以将已验证可用的配置复制到：

```text
/etc/wpa_supplicant.conf
```

并保留了模板备份：

```text
/etc/wpa_supplicant.conf.template.bak
```

### 2. 创建开机脚本

创建并启用：

```text
/etc/init.d/S45wifi-auto
```

脚本流程：

```text
等待 wlan0 出现
→ 设置 wlan0 为 UP
→ 结束旧的 wpa_supplicant
→ 读取 /etc/wpa_supplicant.conf
→ 后台启动 wpa_supplicant
→ 等待无线认证
→ udhcpc 获取 IP、网关、DNS
→ 检查 wlan0 是否有 inet
→ 输出 wifi-auto: OK 或 FAIL
```

## 三、今天掌握的概念

- `wpa_supplicant`：Linux Wi-Fi 客户端，负责 SSID、密码和 WPA/WPA2 认证。
- `udhcpc`：BusyBox 提供的轻量 DHCP 客户端，负责申请 IP、子网掩码、网关和 DNS。
- BusyBox：嵌入式 Linux 的轻量工具集合，包含 `sh`、`cp`、`grep`、`udhcpc` 等命令。
- `/24`：前 24 位表示网络，等价于 `255.255.255.0`。
- `default via 192.168.0.1 dev wlan0`：非本地网络的数据交给默认网关，并从 wlan0 发出。
- `inet 192.168.0.106/24`：wlan0 当前拥有 IPv4 地址。
- `&&`：前一条命令返回 0（成功）时执行后面命令。
- `||`：前一条命令返回非 0（失败）时执行后面命令。
- Shell 中返回码约定为：`0` 表示成功，非 `0` 表示失败。
- `scope global dynamic`：地址是正常可用于网络通信的动态地址。
- `valid_lft` / `preferred_lft`：地址的有效剩余时间和首选使用剩余时间。
- `ping -c 2 192.168.0.1`：向网关发送 2 次 ICMP 测试。
- `ssh root@192.168.0.106`：电脑连接开发板的 Dropbear SSH 服务。

## 四、今天理解的日志来源

| 输出 | 来源 |
|---|---|
| `inet .../24` | `ip -4 addr show wlan0` |
| `default via ...` | `ip route` |
| `lease of ... obtained` | `udhcpc` |
| `Resetting default routes` / `Adding DNS ...` | `/usr/share/udhcpc/default.script` |
| `wifi-auto: OK` | `/etc/init.d/S45wifi-auto` |
| `Starting dropbear sshd: OK` | Dropbear 启动脚本 |

## 五、串口工具经验

- `serial_monitor.ps1` 适合发送一条固定命令并读取输出，不是完整交互式终端。
- `vi` 需要持续传递按键、方向键、`Esc` 和命令行输入，因此应使用 MobaXterm 的交互式 Serial 会话。
- 当前串口参数：`COM9 @ 1500000 8N1`。
- MobaXterm 便携版文件：`MobaXterm_Personal_20.3.exe`。

## 六、Wi-Fi 切换流程（仅完成理解，今天没有切换到新热点）

```text
串口进入交互式终端
→ 备份 /etc/wpa_supplicant.conf
→ 修改 ssid 和 psk
→ 打码检查
→ sync
→ 重新启动 S45wifi-auto
→ 串口查询新 IP
→ 电脑连接同一 Wi-Fi
→ ssh root@新IP
```

切换过程中 SSH 断开是正常的：旧 Wi-Fi 被停止，且新网络可能使用不同网段。今天只模拟和理解了该流程，没有改变开发板当前热点配置。

## 七、已知限制与后续可选改进

- 当前 `S45wifi-auto` 的命令顺序固定，脚本没有正式解析 `start/stop/restart` 参数。
- 当前课程解决的是“开机自动连接”，不是运行中断线后的持续重连守护服务。
- 后续可选：增加重试/监控、实现真正的 start/stop/restart、固定 IP 或自动发现动态 IP。
