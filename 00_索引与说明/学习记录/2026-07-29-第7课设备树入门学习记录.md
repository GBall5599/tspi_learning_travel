# 2026-07-29 学习记录：第 7 课设备树入门

## 一、学习目标

在泰山派当前运行的 Buildroot 系统中只读观察设备树，理解设备树如何连接硬件描述、内核驱动与用户态接口。

## 二、核心认识

```text
DTS / DTSI（源码）
  → DTB（二进制）
  → 启动加载器交给 Linux 内核
  → /proc/device-tree（当前运行时只读视图）
  → 驱动绑定
  → /sys、/dev 用户态接口
```

`/proc/device-tree` 不是 DTS 源码目录，不能从运行时视图倒推出 DTSI 的原始包含关系。

## 三、节点和属性验证

使用：

```sh
ls -ld /proc/device-tree/leds
ls -l /proc/device-tree/model
```

验证：

```text
drw... → leds 是节点目录
-r--... → model 是属性文件
```

根节点型号：

```text
lckfb tspi V10 Board
```

## 四、根节点兼容性

使用 NUL 转换后读取：

```text
lckfb,tspi-v10
rockchip,rk3566
```

理解兼容字符串通常从具体板卡到通用 SoC 排列。

## 五、LED 验证

```text
/proc/device-tree/leds/compatible = gpio-leds
/proc/device-tree/leds/rgb-led-r/linux,default-trigger = timer
/sys/class/leds/rgb-led-r/trigger = [timer]
```

完成设备树、gpio-leds 驱动与 sysfs LED 接口的对应验证。

## 六、REC 按键验证

```text
/proc/device-tree/adc-keys/compatible = adc-keys
/proc/device-tree/adc-keys/restart-key/label = restart
linux,code 原始字节 = 00 00 01 98
0x198 = 408
```

与第 5 课 `evtest /dev/input/event4` 中的 `KEY_RESTART (408)` 完全对应。

## 七、启动参数验证

从 `/proc/device-tree/chosen/bootargs` 读取到 eMMC、根分区、`earlycon`、`ttyFIQ0`、固件版本等参数；理解它们由启动过程最终交给 Linux 内核，但不据此武断判断每个字段一定由 U-Boot 单独生成。
