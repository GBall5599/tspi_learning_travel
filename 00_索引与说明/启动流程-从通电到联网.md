# 泰山派 RK3566：从通电到联网的启动流程

> 适用系统：当前已烧录的 Buildroot 2024.02 + Linux 6.1.141  
> 相关进度：[`学习进度总览.md`](学习进度总览.md)  
> 更新时间：2026-07-23

本文说明开发板从插电/复位，到进入 Linux 命令行，再到连上 Wi-Fi 访问外网，中间依次经历了哪些层。  
目标不是背命令，而是建立一张可复用的系统地图。

---

## 1. 总览图

```text
插电 / 按 RST
   │
   ▼
1. 硬件上电与复位
   │
   ▼
2. 片内 BootROM：决定从哪里启动
   │
   ▼
3. DDR 初始化 + SPL：把内存准备好，加载 U-Boot
   │
   ▼
4. U-Boot：读取分区，加载内核和设备树
   │
   ▼
5. Linux 内核：驱动硬件，挂载根文件系统
   │
   ▼
6. Buildroot 用户空间：shell、服务、文件系统
   │
   ▼
7. 网络接口就绪（wlan0）
   │
   ▼
8. Wi-Fi 关联与认证（wpa_supplicant）
   │
   ▼
9. DHCP 获取 IP（udhcpc）
   │
   ▼
10. 应用层网络验证（ping / SSH / 程序）
```

一句话记忆：

```text
先让芯片活着
→ 再决定从哪启动
→ 再把内存和引导准备好
→ 再启动 Linux
→ 再进入用户空间
→ 最后才联网
```

## 2. 第 1 层：硬件上电与复位

### 你做什么

- 插入 `5V/3A` Type-C 电源适配器；或
- 短按开发板上的 `RST` 键。

### 系统在做什么

```text
电源稳定
  → 芯片复位
  → 时钟与供电轨建立
  → CPU 从固定入口开始执行
```

这一层还没有 Linux，也没有 shell。

### 你可能看到的现象

- 电源指示灯亮；
- 串口暂时无输出，或马上开始输出启动日志。

### 这一层回答的问题

```text
芯片能不能活起来？
```

---

## 3. 第 2 层：片内 BootROM（启动 ROM）

RK3566 芯片内部有一段固化启动代码，断电也不会丢失。  
它的核心任务是：

```text
检查从哪里启动？
```

常见启动来源：

| 情况 | 结果 |
|---|---|
| 正常上电，eMMC 中有可启动固件 | 从 eMMC 启动 |
| 按住 `REC` 再按 `RST` | 进入 Loader，等待电脑烧录 |
| Boot 损坏并通过硬件方式进入救砖模式 | 进入 Maskrom |

### 和你实操的关系

你在 RKDevTool 中看到：

```text
发现一个 LOADER 设备
```

说明板子没有继续进入正常系统，而是进入了可被电脑烧录的模式。

### 这一层回答的问题

```text
第一段可执行代码从哪里加载？
```

---

## 4. 第 3 层：DDR 初始化 + SPL（一级引导）

串口日志前半段通常类似：

```text
DDR ...
LPDDR4
Size=2048MB
change to: 1056MHz
...
U-Boot SPL ...
```

### 4.1 为什么必须先初始化 DDR？

CPU 片内 SRAM 很小，真正运行系统和加载程序需要外部内存。  
所以启动时必须先：

```text
识别内存颗粒
  → 训练读写时序
  → 把内存调到可用频率
  → 让后续程序可以放到 DDR 中运行
```

对本板而言：

```text
Size=2048MB  →  2GB LPDDR4 运行内存
```

### 4.2 SPL 做什么？

SPL（Secondary Program Loader）是很小的一级引导程序，任务很单纯：

```text
内存可用
  → 找到存储设备（TF / eMMC）
  → 加载完整 U-Boot 到内存
  → 跳转到 U-Boot
```

日志中可能出现：

```text
Trying to boot from MMC2
Trying to boot from MMC1 / MMC0
```

若未插入 TF 卡，`MMC2` 相关报错通常可忽略。

### 这一层回答的问题

```text
内存能不能用？
完整引导程序能不能被加载？
```

---

## 5. 第 4 层：U-Boot（二级引导）

日志中类似：

```text
U-Boot ...
DRAM: 2 GiB
MMC0: HS200 ...
Starting kernel ...
```

### U-Boot 的核心职责

```text
识别 eMMC 与分区
  → 读取启动参数 / 内核 / 设备树
  → 设置启动命令行
  → 把控制权交给 Linux 内核
```

### 你需要记住的三件事

1. **知道板子是谁**  
   例如：
   ```text
   Machine model: lckfb tspi V10 Board
   ```

2. **知道从哪个存储启动**  
   例如：
   ```text
   mmcblk0 / eMMC
   ```

3. **准备好内核和设备树，然后启动内核**  
   ```text
   Starting kernel ...
   ```

### 关于 `MMC0: HS200, 200Mhz`

这不是 CPU 主频，也不是 2GB 内存容量。  
它表示：

```text
eMMC 存储接口已用 HS200 高速模式工作，接口时钟约 200MHz
```

对本板可理解为：

```text
U-Boot 已成功识别并高速访问板载 eMMC
```

### 这一层回答的问题

```text
加载哪一个 Linux 内核？
用哪套板级描述（设备树）启动？
```

---

## 6. 第 5 层：Linux 内核

日志中出现：

```text
Linux version 6.1.141
...
mmcblk0: ... 14.6 GiB
```

说明控制权已经从 U-Boot 交给 Linux 内核。

### 内核主要做什么

```text
初始化 CPU、中断、调度器
  → 加载各类驱动（eMMC、USB、Wi-Fi、串口、HDMI 等）
  → 挂载根文件系统
  → 启动第一个用户态进程（init）
```

### 内核 vs 用户空间

| 层次 | 谁在运行 | 你看到什么 |
|---|---|---|
| 内核 | Linux 内核代码 | `Linux version`、驱动日志 |
| 用户空间 | shell、服务、应用程序 | `root@taishanpi:/#` |

例如：

```bash
uname -a
```

本质是在问内核：

```text
你是谁？版本多少？架构是什么？
```

当前答案类似：

```text
Linux taishanpi 6.1.141 ... aarch64 GNU/Linux
```

### 这一层回答的问题

```text
硬件如何被抽象成设备、分区、网络接口和文件系统？
```

## 7. 第 6 层：Buildroot 用户空间

当串口出现：

```text
root@taishanpi:/#
```

说明：

```text
内核已起来
根文件系统已挂载
init 已启动基本服务
交互 shell 可用
```

### 7.1 系统身份

```bash
cat /etc/os-release
```

当前结论：

```text
Buildroot 2024.02
Linux 6.1 相关构建信息
rockchip_rk3566
```

### 7.2 资源视图

```bash
free -h
df -h
cat /proc/partitions
```

对应理解：

| 命令 | 观察对象 |
|---|---|
| `free -h` | 2GB 内存使用情况 |
| `df -h` | 已挂载文件系统及剩余空间 |
| `cat /proc/partitions` | eMMC 分区布局 |

### 7.3 当前主要分区

```text
mmcblk0        整个 eMMC（约 14.6 GiB）
mmcblk0p6      根文件系统 /
mmcblk0p7      /oem
mmcblk0p8      /userdata
```

### 7.4 持久化与临时目录

| 路径 | 是否持久 | 用途 |
|---|---|---|
| `/tmp` | 否/弱持久 | 临时文件 |
| `/run` | 否 | 运行时状态 |
| `/` | 是 | 系统与程序 |
| `/userdata` | 是 | 用户数据优先位置 |
| `/oem` | 是 | 厂商配置/资源 |

已验证闭环：

```text
写入 /userdata/lesson.txt
  → sync
  → reboot
  → 再次读取，内容仍在
```

### 这一层回答的问题

```text
系统能否作为一台可交互的 Linux 设备使用？
文件应该放在哪里才不会重启丢失？
```

## 8. 第 7~10 层：从“能进系统”到“能上网”

### 重要区分

```text
系统启动完成  ≠  已经联网
```

出现 `root@taishanpi:/#` 只说明 Linux 用户空间可用。  
联网还要继续走完下面几步。

### 8.1 网络接口就绪

```bash
ip addr
ifconfig wlan0
```

常见接口：

| 接口 | 含义 |
|---|---|
| `lo` | 本机回环，`127.0.0.1` |
| `eth0` | 有线网口 |
| `wlan0` | 主 Wi-Fi 接口 |
| `wlan1` | 辅助/虚拟无线接口 |

若看到：

```text
wlan0 UP
但没有 inet 192.168.x.x
```

含义是：

```text
网卡已启用，但还没连热点，也还没拿到 IP
```

### 8.2 Wi-Fi 扫描

```bash
iwlist wlan0 scanning
```

本板 Wi-Fi 为 AP6212A，主要面向 2.4GHz。  
扫描成功后会看到类似：

```text
ESSID:"ccccc2.4g"
Frequency:2.412 GHz
Signal level:-59 dBm
```

### 8.3 关联与认证

```bash
wifi-connect.sh ccccc2.4g '<密码>'
```

底层大致过程：

```text
生成 wpa_supplicant 配置
  → 启动 wpa_supplicant
  → 关联 SSID
  → 完成 WPA2 认证
  → Link UP
```

关键日志：

```text
Connecting with ... ssid "ccccc2.4g"
Link UP
connection succeeded
```

此时只说明无线链路通了，还不等于可以访问网络。

### 8.4 DHCP 获取地址

```bash
udhcpc -i wlan0 -n -q
```

过程：

```text
广播 DHCP 发现
  → 路由器分配地址
  → 配置 IP / 网关 / DNS
```

当前实测结果：

```text
IP：192.168.0.105/24
网关：192.168.0.1
DNS：192.168.0.1
```

### 8.5 分层验证网络

```bash
ping -c 3 127.0.0.1    # 本机协议栈
ping -c 3 192.168.0.1  # 局域网网关
ping -c 3 8.8.8.8      # 外网 IP
ping -c 3 baidu.com    # DNS + 外网域名
```

对应关系：

| 测试 | 验证内容 |
|---|---|
| `127.0.0.1` | 本机 TCP/IP 栈是否正常 |
| 网关 | 局域网链路与路由是否正常 |
| `8.8.8.8` | 外网 IP 是否可达 |
| `baidu.com` | DNS 解析与域名访问是否正常 |

### 这一层回答的问题

```text
板子能否从“本地 Linux”变成“可联网的开发设备”？
```

## 9. 两套启动链对照

### 9.1 原来的 Android 11

```text
上电
 → DDR
 → U-Boot SPL / U-Boot
 → Linux 4.19.193
 → Android init
 → bootanim
 → Launcher3
 → sys.boot_completed=1
```

### 9.2 当前 Buildroot

```text
上电
 → DDR
 → U-Boot SPL / U-Boot
 → Linux 6.1.141
 → Buildroot init / 服务
 → root@taishanpi:/#
 → wlan0
 → Wi-Fi 连接
 → DHCP
 → ping / SSH
```

相同点：

- 前半段引导骨架类似（DDR → U-Boot → Kernel）

不同点：

- Android 最后进入图形系统和桌面；
- Buildroot 最后进入精简 Linux shell 与服务。

## 10. 你做过的实操分别落在哪一层

| 实操 | 对应层 |
|---|---|
| 接串口、抓 `DDR/U-Boot` 日志 | 硬件 + 引导层 |
| RKDevTool 发现 LOADER | BootROM/引导进入烧录模式 |
| 烧录 Buildroot 镜像 | 改写 eMMC 中的引导和系统 |
| `uname -a` / `os-release` | 内核 + 用户空间身份 |
| `free` / `df` / `partitions` | 内核资源 + 文件系统 |
| `/userdata` 写文件并重启验证 | eMMC 持久化 |
| `iwlist scan` | Wi-Fi 驱动与扫描 |
| `wifi-connect.sh` | 无线关联与认证 |
| `udhcpc` | DHCP 获取地址 |
| `ping baidu.com` | 完整网络可用性 |

## 11. 排错时应按层定位

不要一出问题就盲目重烧系统。先问：

```text
故障卡在哪一层？
```

| 现象 | 优先怀疑 |
|---|---|
| 完全无串口输出 | 供电、串口接线、USB-TTL、波特率 |
| 只有 DDR/SPL，进不了 U-Boot | 引导加载、eMMC/启动介质 |
| 有 U-Boot，无 `Linux version` | 内核镜像、启动参数、设备树 |
| 有内核日志，无 `root@` | 根文件系统挂载、init |
| 有 shell，无 `wlan0` | Wi-Fi 驱动/固件/天线 |
| 有 `wlan0` 但扫不到热点 | 天线、2.4G/5G、射频环境 |
| 已 Link UP 但无 IP | DHCP |
| 有 IP 但域名不通 | DNS |
| 能 ping IP 不能 SSH | 服务、防火墙、地址/端口 |

## 14. 一句话总结

泰山派从通电到联网，本质是一条“逐层交接控制权”的流水线：

```text
硬件复位
 → 选择启动源
 → 初始化内存并加载引导
 → U-Boot 加载内核
 → Linux 接管硬件
 → Buildroot 提供 shell 与服务
 → Wi-Fi 关联
 → DHCP 拿地址
 → 网络可被应用使用
```

看懂这条链，后面学习设备树、驱动、显示、应用开发时，才知道自己在改哪一层。
